# LiveMedCard — архітектура реалізації (TRACE)

Повноцінна програмна реалізація MVP кейсу LiveMedCard за фреймворком **TRACE**
(Zabolotnii, arXiv:2605.03838). Кожен шар — окремий модуль; головний інваріант:
**сигнали безпеки формуються детерміновано на факт-сторі (L1/L2a), а не генеративною
моделлю (L2b).**

## Потік даних (E2E)

```
Документ (фото/текст)
   │
   ▼  фото → текст (LMC_IMAGE_OCR): vision-LLM `ocr.py` | PP-OCR `ppocr.py` (бокси → рядки)
   │
   ▼  L2b  — Stage 1 (MedGemma → SGR-summary) → Stage 2 (детермінований deterministic_extract)
             дефолт offline: StubExtractor (Stage 2 напряму по сирому тексту)
ExtractionResult  (FHIR: Observation / Condition / MedicationRequest + Provenance; + DocumentReference — free-text)
   │
   ├──► FactStore (KV-T)   — джерело істини для кількісного (триплет несе source_doc_id + source_span)
   ├──► KnowledgeGraph     — зв'язки + провенанс (ребра derived_from факт→Document; вузол Document несе summary)
   └──► DocumentReference  — free-text іпостась (Stage 1 summary / сирий текст у stub)
   │
   ▼  L1  — детермінований якір: взаємодії ліків, дозові межі (по відкритій БД)
   ▼  L2a — класичний аналіз: тренди й вихід за референс-межі на KV-T
list[Signal]
   │
   ▼  L3  — політика роутингу/ескалації; при невпевненому витязі — друга спроба
            альтернативним L2b у межах бюджету, і лише потім людина
Decision  (auto | ескалація до L4-людини)
   │
   ▼  L4  — людина (родина / лікар) приймає рішення і воно ЗАПИСУЄТЬСЯ
ReviewEntry (роль, дія, час на кейс) → метрики нагляду · BoundaryEvent при
            експорті з непереглянутим обов'язковим
```

Q&A (grounded): запит → детермінований ретрив по FactStore+Graph → відповідь
природною мовою з посиланням на документи-джерела (провенанс). Лаб/ліки-інтенти —
за keyword-мапами; freetext-гілка — **ранжований span-aware ретрив** (`retrieval.py`:
лексичне ранжування offline, опційно семантичний косинус через embeddings). LLM тут
не робить висновків про безпеку — ретрив лише відбирає пасажі, не породжує сигналів.

## Ключові рішення

- **`Signal` — єдиний тип** для L1 і L2a (`layer`, `kind`, `severity`, `subjects`,
  `confidence`). Детерміновані сигнали мають `confidence=1.0`. Це роз'єднує L3 від
  реалізацій L1/L2a.
- **L2b ізольований**: `StubExtractor` (дефолт, offline) парсить український текст
  за словником `data/vocab.json`. Інтерфейс `Extractor` дозволяє підмінити на
  реальну MedGemma без змін конвеєра. Екстрактор ставить лише `confidence` витягу,
  **не** висновок про безпеку.
- **Двоетапний L2b** (метод *LLM StructCore*): Stage 1 (MedGemma) згортає текст у
  SGR-summary (free-text іпостась → FHIR `DocumentReference`); Stage 2 витягує з
  summary KV-T факти з **датою на факт**. Два режими Stage 2:
  - `two_stage` — `deterministic_extract` (regex + `vocab.json` → LOINC);
  - `two_stage_lora` — FT MedGemma база+LoRA генерує KVT4 `{cluster,keyword,value,
    timestamp}`, часті лаби мостяться keyword→LOINC (два llama.cpp-сервери).

  У будь-якому режимі стохастика LLM впливає лише на recall; сигнали безпеки
  L1/L2a лишаються детермінованими на FactStore.
- **Stage 1 — змінний драйвер** (`LMC_IMAGE_OCR`), і вибір між ними робиться не
  за якістю транскрипції. Виміряно (`docs/ocr_stage1_benchmark.md`): рушій, що
  віддає готовий текст, групує лабораторну таблицю по колонках, значення
  перестає стояти впритул до терміна, і документ дає **нуль** кодованих
  показників при майже бездоганному тексті. `ppocr.py` віддає бокс на рядок, з
  якого рядок збирається назад — і ті самі показники доходять до картки. Тому
  критерій — **чи є геометрія**, а не покриття підрядками. 4B-VLM лишається
  якорем для рукопису, де програють обидва (2/4 проти 4/4).
- **Словник шукається по згорнутих омоглифах** (`l2b_extractor._fold`): OCR
  кирилиці систематично русифікує українську (`Креатинін→Креатинин`), а точний
  збіг такий показник втрачає разом із його сигналом. Згортання застосовується
  до **обох** боків порівняння й лише всередині пошуку — згортання самого тексту
  зводить «Глікований гемоглобін» до «гемоглобін» і перетворює HbA1c 7.6 % на
  гемоглобін у межах норми, тобто міняє пропущений факт на хибно нормальний.
- **L3 ескалює до людини** за двома незалежними приводами: детермінований сигнал
  `severity ∈ {major, critical}` (незалежно від впевненості витягу — реальна
  небезпека завжди потребує рішення людини) або впевненість витягу нижча за
  виведений з вартостей поріг. **Перед ескалацією — друга спроба:**
  `should_reinvoke` витрачає бюджет (`LMC_REINVOCATION_BUDGET`, типово 1) на
  альтернативний екстрактор, якщо той зареєстровано; береться **кращий** з двох
  результатів, тож повторна спроба коштує лише часу. Перевикликаємо **лише**
  через низьку впевненість витягу — знайдена небезпека не привід перевитягувати,
  сигнал уже достовірний. Ширшого стану (накопичена впевненість між документами,
  розширення контексту, звірка L2a/L2b) немає, і це назване обмеження.
- **L4 — шар із записуваними діями, а не бейдж.** `governance.py` декларує межу
  автономії (major/critical → рішення за людиною; moderate → дорадчо; info →
  автономно). `POST /review` пише `ReviewEntry` (роль, дія, ключ сигналу або
  документа, час на кейс); журнал переживає знімок і Bundle. `card_decision`
  рахує ескалацію лише за **непереглянутим**, тож робота людини має видимий
  наслідок. Експорт картки з непереглянутими обов'язковими сигналами пише
  `BoundaryEvent` — перетин межі не блокується, але фіксується. Звідси метрики
  нагляду в `/metrics.supervision`: OvR, RBI, SNR, покриття, ABC-excursions.
- **Багаторівнева приватність відповідей (opt-in).** Дефолт Q&A — локальний
  grounded-режим (0 даних покидає пристрій). Опційно — «розумні відповіді»: до
  сильнішої моделі передається **лише** Stage-1 de-identified summary, на
  privacy-контрактованому (zero-retention/DPA) або self-hosted ендпойнті.
  Принцип — **хмара формулює мову, локаль володіє фактами й безпекою**: модель
  дістає de-id summary + уже пораховані факти/сигнали як grounding, а локальний
  шар re-grounds відповідь проти FactStore перед показом. Ця модель **не живить
  L1/L2a** і не породжує чисел чи висновків про безпеку; L3 маршрутизує (просте →
  локально, складне → opt-in). De-id — defense-in-depth (ймовірнісна, не
  анонімізація, слабша для UA), тож перевага приватному/self-hosted ендпойнту;
  recall de-id і приріст якості вимірюються перед релізом.
- **Провенанс — інваріант + span-рівнева прив'язка.** `pipeline._assert_provenance`
  відхиляє витягнутий факт без `source_doc_id` (`ValueError`) на межі `ingest`, тож
  кожен KV-T-триплет гарантовано має документ-джерело й ребро графа. `source_span`
  (`Provenance`/`KVTFact`) — offset у free-text іпостасі (детермінований екстрактор
  рахує з regex-матчів; для LLM-KVT — best-effort null). Це живить графову БЗ і
  точний grounding для детальніших відповідей.
- **Довідкові БД** (`data/interactions.json`, `dose_limits.json`,
  `reference_ranges.json`) — відкриті, версіоновані, читаються детерміновано.
  Коди узгоджені: RxNorm (ліки), LOINC (аналізи), SNOMED (діагнози).

## Запуск

```bash
uv run python -m livemedcard.demo          # E2E демо в терміналі
uv run uvicorn livemedcard.api:app         # веб-UI на http://127.0.0.1:8000
uv run --extra dev pytest                  # тести (274 шт.)
uv run --extra dev ruff check livemedcard tests   # лінтер (як у CI)
```

## Додаткові модулі (архітектурні покращення)

- `config.py` — централізовані налаштування (пороги/шляхи; env `LMC_*`,
  зокрема `LMC_STUB_CONFIDENCE`).
- `refmodels.py` — типізовані моделі довідників; `reference.range_for(loinc, sex)`
  дає межі з урахуванням статі пацієнта (проброс sex через L2a/Q&A/демо).
- `bundle.py` — експорт/імпорт стану як стандартного **FHIR Bundle**.
- `repository.py` + `LiveMedCard.snapshot`/`from_snapshot` — персистентність у
  локальний JSON (local-first; env `LMC_PERSIST_PATH`).
- Аудит рішень L3 і метрики (`/audit`, `/metrics`); `LiveMedCard` — джерело істини
  FHIR-ресурсів, `FactStore`/`KnowledgeGraph` — похідні проєкції.

## Зміцнення за зовнішнім архітектурним ревʼю (livemedcard.html)

- **Потокобезпечний стан API**: картка інкапсульована в `_State` під
  `threading.Lock` (sync-ендпойнти FastAPI виконуються в пулі потоків);
  жодного `global`. Конкурентний мікс запитів покрито тестом.
- **Стабільні id ресурсів**: L2b генерує id як хеш змісту
  (`документ|код|значення|час`), а не порядковий номер — ідемпотентність
  переживає зміни словника і відновлення зі старих знімків; ідентичні повторні
  згадки колапсують в один факт.
- **Типізований аудит**: `dto.AuditEntry` (Pydantic) замість «сирих» dict;
  биті записи журналу відхиляються валідацією при відновленні знімка.
- **Кешовані незмінні довідники**: loader-и `reference.py` під `lru_cache`
  повертають tuple/`MappingProxyType` **заморожених** моделей — без перебудови
  об'єктів на кожен виклик і без ризику мутації спільного стану; мапа пар
  взаємодій L1 будується один раз.
- **Індекс FactStore за LOINC**: `series()`/`loincs()` без лінійного проходу
  всього стору.
- **Захист знімка**: пошкоджений JSON персистентності → явний `ValueError`
  (сервер не стартує порожнім і не перезаписує дані автозбереженням).
- **CI**: `ruff check` + `pytest`; HTTP-контракт API покрито TestClient-тестами.

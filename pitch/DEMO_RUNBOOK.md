# LiveMedCard — сценарій живого демо (Zoom, 5 хв, укр.)

Демо триває **~90–120 c** усередині 5-хвилинного пітчу (на слайді 3 деку). Мета —
довести три речі за півтори хвилини: **(1)** продукт працює сьогодні, **(2)** AI
структурує реальний документ, **(3)** сигнали безпеки — детерміновані, не галюцинація.

---

## Пер­ед-польотний чеклист (за 10 хв до пітчу)

- [ ] **Хостована картка тепла:** відкрити <https://docua-livemedcard.hf.space>, натиснути
      **«Load demo card»** і переконатися, що картка заповнилась (4 док., 8 сигналів). Це
      «безпечний» шлях — детермінований `stub`, без GPU/мережевих ризиків. Картка
      **per-session**: кожен відвідувач має власну копію, тож журі, що клікає паралельно,
      вас не зіб'є.
- [ ] **Мова демо = мова інтерфейсу.** Картка стартує **порожньою**; кнопка вантажить набір
      тією мовою, якою відкрито UI (EN → англомовні документи, UA → українські). Набори
      дзеркальні: ті самі значення, ті самі 8 сигналів. Для міжнародного журі — лишайте **EN**.
- [ ] **Кліп NuExtract3 готовий** (див. нижче) — сценічний шлях для показу AI на документі.
      Локальний сервер на :1299 для сцени **не потрібен**: показуємо кліп, а живий сайт
      робить OCR через хмарний Lab. Піднімати :1299 — лише якщо свідомо йдете в live.
- [ ] Вкладки браузера: (1) хостована картка, (2) кліп/відео. Зайве закрити.
- [ ] Зум: демо-екран перевірено, шрифт UI читабельний на проєкторі.
- [ ] **Fallback напохваті:** `pitch/clip/demo_full_en.mp4` — **записаний дубль усього демо**
      (45 c, справжній прогін по живому сайту: порожня картка → «Load demo card» → таймлайн →
      сигнал варфарин+аспірин → список документів → оригінал із підсвіченим реченням → граф знань →
      фото бланку через хмарний OCR → новий факт у таймлайні → Q&A англійською й українською →
      експорт FHIR). Якщо мережа впала — показуєте його й коментуєте так само.

## Сценарій (тайм-коди — орієнтир)

**0:00 — Жива картка (хостована).**
Відкрити картку — вона **порожня**. Натиснути **«Load demo card»** → відкриється **перегляд
вхідних документів**. Не проскочити його: «Ось **сирі документи**, як їх бачить картка. Прочитайте
їх — потім перевірите, що з них витягнуто. Зверніть увагу: **варфарин і аспірин лежать у різних
документах**, між ними рік. Жоден лікар не бачив обох.» → **«Завантажити в картку»**.
«Це справжній прототип, він зараз онлайн. Картка мами, 70 років — чотири документи з різних
джерел, зведені в **один таймлайн**.» → показати: **Creatinine 88 → 104 → 121 → 135**.
Праворуч — **Submitted documents**: клік по рядку відкриває **оригінал документа**. «Нічого не
приховано: кожне число можна повернути до документа, з якого воно взято.» Якщо є 10 секунд —
натиснути **Knowledge graph**: клік по вимірюванню підсвічує пацієнта і документ-джерело.

**0:20 — Сигнал безпеки (детермінований момент).**
Навести на червону панель. «Система сама помітила: **Варфарин + Аспірин** — небезпечна взаємодія,
ризик кровотечі. І це **не галюцинація мовної моделі** — сигнал порахований детерміновано на
фактах, шар L1. Плюс перевищена доза метформіну й тренд креатиніну вгору.»

**0:45 — AI на реальному документі (NuExtract3).**
«А тепер найважче — витягнути це зі **справжнього документа**.» Показати фото лабораторного
бланку (`pitch/clip/lab_report_en.jpg` — **англомовний**: доповідь українською, але екран
міжнародне журі має читати без перекладу) → запустити кліп/інференс:
- Крок 1: **фото → markdown** (модель дослівно читає бланк).
- Крок 2: **markdown → структуровані факти** (Creatinine 135, Potassium 5.1, Fasting glucose 6.8,
  HbA1c 7.6 — усі з датою 2024-10-15).
«Модель локальна, on-device. Вона лише **витягує факти** — висновки про безпеку робить
детермінований шар, не вона.»

**1:10 — Питання природною мовою.**
У полі Q&A спитати **англійською**: **«What is the latest creatinine?»** → відповідь
«Creatinine: latest value 135.0 µmol/L (2024-10-15)…» **із посиланням на 4 джерела**.
«Відповідь заземлена на факти, з провенансом, і **мовою питання**.» Якщо лишається секунда —
одразу спитати **«Який останній креатинін?»** і показати ту саму відповідь українською. Це
сильніший доказ білінгвальності, ніж будь-яке слово про неї.

**1:25 — Експорт і закриття.**
Клік **«Експорт FHIR»**. «Стандартний FHIR-Bundle — картку можна передати лікарю чи в eHealth.»
Закриття: «**Локально. Детерміновано на безпеці. Працює вже сьогодні.**»

## NuExtract3-кліп: як зробити й показати

**Рекомендація:** показувати **записаний кліп** (screen-capture термінала/UI, за потреби прискорений
×2), а не live-інференс — ~25 c очікування на сцені задовго, і знімає ризик черги/латентності.
Live-варіант лишити опційним, якщо впевнений (локальний :1299 стабільний).

**Відтворити результат локально** (модель має бути піднята на :1299):
```bash
python3 - <<'PY'
import sys, base64; sys.path.insert(0, ".")
from livemedcard.layers import l2b_nuextract
b64 = base64.b64encode(open("pitch/clip/lab_report_en.jpg", "rb").read()).decode()
md = l2b_nuextract.image_to_markdown(b64)          # фото → markdown
print(md)
print(l2b_nuextract.extract_facts(md))             # markdown → KVT
PY
```

**Показати в застосунку live** (замість термінала): підняти локально в режимі NuExtract і
завантажити фото через `/ingest/image`:
```bash
LMC_EXTRACTOR=nuextract uv run uvicorn livemedcard.api:app
# у UI: «+ Додати документ» → зображення → pitch/clip/lab_report_en.jpg → новий показник лягає в таймлайн
```

**Готовий кліп** — `pitch/clip/nuextract_demo_en.mp4` (7.6 c, 1280×900; `…​.gif` — той самий
запис для вставки в дек). Це **справжній прогін через живий інтерфейс**, не монтаж:
картка з трьох ранніх документів (Creatinine 88 → 104 → 121, 5 сигналів) → завантаження
фото бланку → «Reading (OCR)…» → у таймлайн лягає **четверта точка 135 µmol/L (2024-10-15)**,
сигналів стає **8**, рішення — **escalated to human (L4)** → клік по чипу `doc-ocr-…` відкриває
**розпізнаний оригінал**. Запис прискорено ≈2× (реальний прогін — 17 c).

**Інші артефакти** (`pitch/clip/`): `lab_report_en.jpg` (синтетичний бланк),
`nuextract_markdown_en.md` (вихід Stage 1), `nuextract_kvt_en.json` (вихід Stage 2).
Українські двійники (`*_ua.*`) — показувати, лише якщо журі спитає «а українською?».

**Заміряно на цьому бланку** (11.07, локально, Apple Silicon, NuExtract3 Q4_K_M на llama.cpp):
Stage 1 = **17.1 c**, Stage 2 = **4.6 c**; **4 з 4 значень з одиницями й датою**
(Creatinine 135 µmol/L, Potassium 5.1 mmol/L, Fasting glucose 6.8 mmol/L, HbA1c 7.6 %, усі
2024-10-15). У хмарному ZeroGPU Lab той самий бланк — ≈55 c. Дата на факти не стоїть у рядках
таблиці: її беруть із поля **«Collected»** того ж витягу (див. нижче про дати).

## Межа детермінізму (тримати в голові, якщо журі спитає)

Модель (NuExtract3/MedGemma) **лише витягує факти** → впливає на **recall**. Сигнали безпеки
(взаємодії, дози, тренди, межі) рахуються **детерміновано на FactStore** (L1/L2a). Часті лаби
мостяться keyword→LOINC детермінованим містом; решта — free-form, без сигналу до підтвердження коду.

**Формулювати точно — не переобіцяти.** Правильно: «LLM не ухвалює рішень безпеки й **не може
вигадати** взаємодію; після витягу взаємодії та дози перевіряються детерміновано». Неправильно:
«навіть якщо модель помилилась, взаємодію не пропустимо» — **це неправда**: якщо модель не витягла
один із двох препаратів, у L1 просто немає пари для перевірки. Саме тому неповний або невпевнений
витяг **ескалюється до людини** (L3: `confidence < 0.6` → L4), а не вдає успіх. Це і є чесна
відповідь на питання «а якщо AI помилиться?»: помилка стає **видимою ескалацією**, а не тихим
пропуском.

Так само чесно про **дати**: якщо в документі дати немає, показник **не вдає** виміряний
сьогодні — у картці стоїть «no date in document» (дата завантаження, явно позначена). Якщо
дата в документі є, але в шапці («Collected: 2024-10-15»), нею датуються значення бланка.
Дату видачі («Reported») для цього **не беремо** — це не дата вимірювання.

Так само чесно про **одиниці**: значення в неспівставних одиницях (глюкоза `100 mg/dL` проти меж
`3.9–6.1 mmol/L`) **не** дає сигналу «вище норми» — L2a натомість піднімає `unit_mismatch`
(«перевірку меж не виконано»). Хибний сигнал у медицині гірший за відсутній.

## «На чому це працює?» — залізо (якщо журі спитає)

Два шари з різним апетитом до заліза (деталі — `README.md` → «Мінімальна конфігурація»):

- **Шар безпеки — featherweight** (чистий Python, без ML): таймлайн, сигнали L1/L2a,
  Q&A-grounding, FHIR — іде **навіть на телефоні / Raspberry Pi**. Повна безпека — на будь-якому залізі.
- **Розуміння тексту/фото** (4B GGUF через llama.cpp): **AI-мінімум — 8 ГБ RAM, CPU-only**
  (ноутбук/міні-ПК); комфортно — **Apple Silicon M1+ або GPU ≥6 ГБ**; on-device (продукт) —
  флагман-смартфон. Екстракція документа не real-time → секунди навіть на CPU-мінімумі.

Меседж: «local-first — не гасло; повна безпека на будь-якому залізі, а розуміння — від звичайного ноутбука».

## ZeroGPU Lab — roadmap-доказ, не сценічний шлях

Хмарний ZeroGPU OCR Lab (окремий Space) **уже працює** — доведено E2E (фото → markdown → KVT4 →
Observations з коректним LOINC). Але у **живий пітч його НЕ ставимо**: ZeroGPU має денну квоту й
cold-start (~45 c). На сцені — **локальний кліп** (нуль квоти, нуль ризику). Space згадуємо усно як
готовий roadmap-доказ хмарного треку.

## Якщо журі саме клікне «завантажити фото» на живому сайті

Це працює по-справжньому: фото йде в хмарний ZeroGPU Lab (NuExtract3), розпізнається і
лягає в таймлайн із LOINC-кодами. **Але триває ~70–90 c** — UI попереджає про це окремим
повідомленням, тож пауза не читається як зависання. **На сцені цей шлях не чіпати** —
кліп надійніший і вкладається в тайм-код. Якщо журі спитає «а це справді працює?» —
запросіть натиснути самостійно **після** пітчу.

**Золоте правило:** живий шлях — завжди на **детермінованому `stub`** (100% відтворювано);
NuExtract3 — «вишенька» через записаний кліп. Нуль хмарної залежності у критичні 5 хвилин.
